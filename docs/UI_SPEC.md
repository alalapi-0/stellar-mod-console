# 玩家界面与视觉计划

读者是设计/前端/游戏内实现者；完成技术实验、真实游戏 UI 采样或玩家反馈后更新。本轮只有设计要求，没有 Figma 文件、UI 实现或视觉验收。

## 视觉方向

以[官方 Steam 展示](https://store.steampowered.com/app/3489700/Stellar_Blade/)作为合法参考入口，执行轮读取当前游戏真实设置/装备/HUD 表面并提炼布局、密度、字体层级和输入提示。当前尚未对真实装备菜单做设计采样，下面是待验证方向而非“已经复制游戏风格”。

采用深色半透明主面板、克制的冷色高亮、清晰分区和细边缘。体积感由背景层、面板层、卡片层、浮动提示层及边缘光/柔阴影形成；不把厚重模糊、全屏发光或强烈 3D 动效作为默认。焦点项有明确抬升/对比和输入提示，背景仍能辨认游戏状态。

字体、图标、纹理和声音用自有或明确许可资产，不复制游戏 UI、Mod Hub CSS 或受保护主题。中文完整字形和字体授权单独核实。提供缩放、减少动效、低开销外观与清晰对比；不要只靠颜色表达危险。

设计文件按当前 ui-design-governance 技能使用 Figma。功能原型可先使用已验证 UMG 控件，视觉稿不替代真实游戏内渲染验收。

## 信息结构

- 顶栏：当前配置档、游戏/适配状态、未应用变化、关闭/帮助。
- 分类导航：总览；服装/身体/外观；物理/动作；镜头/摄影；玩法/辅助；画质/性能；音频/界面；工具/配置；诊断/恢复。
- 中栏：搜索/筛选的 MOD 或功能卡。显示名称、当前状态、应用时机和简短影响，不展示原始 ID、文件 hash 或日志堆栈。
- 详情栏：效果、前置、互斥与将被替换项、参数/配套、性能和难度说明、恢复入口；工程细节放可折叠诊断。
- 工具页：一个页面承载一个经过适配的能力组合；允许切换页面/布局，不用多个互相争抢焦点的叠加菜单。
- 变更栏：立即应用或退出后应用方案，显示当前值和待应用值，不把提交中当已启用。

大型清单按分类、搜索、分页/虚拟列表逐步显示；菜单关闭时停止昂贵预览和不必要刷新。不要求一次把所有 796 旧选项渲染在屏幕上。

## 互斥交互

互斥组使用单选或“替换当前选择”，不能用看似独立的多选框。选择新项之前明确说明“会停用 A，并启用 B 的配套”；后端规划成功才显示待应用。规则拒绝时说明具体原因，不宣称每次覆盖都必然崩溃。

缺前置、版本不符、未验证组合和重启项有独立状态。默认禁用未知危险应用，仍能查看详情与解决办法。用户不需要懂 pak/chunk/DLL 才能做正确选择。

示例玩家文案：
- “此版本会替换当前版本，两个版本不能同时启用。”
- “需要退出游戏后应用；当前游戏仍使用原配置。”
- “尚未在当前版本测试，暂不允许与这项一起启用。”
- “缺少对应物理资源，启用该修复曾导致角色穿过场景；当前已关闭。”
- “提高容错窗口，会降低战斗难度。”
- “作者描述可能增加显存使用；本机尚未测量。”
- “应用失败，仍使用原选择。查看原因 / 重试前检查。”

## 热键、输入与状态

R01 收集实际绑定，R06 决定可配置菜单热键，避开 CNS/Camera/Kittens/ATOOL/RandomSwitch 和游戏默认绑定。前端与后端共享键位声明及冲突结果，不能只发警告却同时绑定。

需覆盖鼠标、键盘与手柄导航；关闭/取消返回上一层，关键操作有一致按键提示。打开时不得把玩家输入误传给战斗或摄影；关闭、死亡、切图、过场和外部菜单共存时恢复恰当模式。

必须设计 loading、empty、source missing、dependency missing、disabled、unknown、conflict、applying、rollback、restart required、runtime unavailable 状态。不能让源文件失联后仍显示可用。

## 参数和引导字段

每项说明最少包含：用途和作者来源；影响对象；立即/安全时/重启；互斥与前置；可调边界；可能的存档/玩法效果；GPU/显存/CPU影响证据；难度降低/便利性/纯外观分类；恢复默认方法。危险参数不默认最大化，不把作弊/便利误标为性能优化。

性能标注区分 measured、author_claim、estimate、unknown。实测必须附同场景/画质/分辨率/硬件条件，不能编造每个 MOD 的显存或 FPS。未知压力项进入待测列表，并提供简化预览/停用方案。

个人视觉验收由用户在真实游戏中评估；截图、静态渲染、工具默认控件或设计稿不能代替功能和审美确认。
