# 目标、范围与验收

读者是实现者、审查者和玩家文档作者；需求变化或实测新限制时更新，不能为完成一小部分偷偷缩小总目标。

## 两级交付

**M1 个人使用目标**：我的新旧剑星 MOD 在同一系统中完整清点和管理；提供安全兼容配置、互斥选择、配套前置与身体策略；通过快捷键打开游戏内控制台，换服装/皮肤、调整已有工具能力和其他 MOD 参数，清楚展示哪些可立即应用、哪些需重启、哪些仍缺条件。界面贴近游戏、具有体积感，并经过真实游戏与性能验收。

**M2 公开产品目标**：把经过验证的系统做成可供其他玩家安装的开源 MOD，具备可移植路径、安装/升级/卸载、第三方适配扩展、许可清单、版本矩阵、恢复指引和公开发行候选。源码仓库公开已授权；具体发行审批是最后一步，不用本轮规划代替发布授权。

## 不可省略的要求

1. 固定输入快照，所有相关包、散装文件和未完成下载均有记录；不能把包数、安装变体数和可选衣服/参数数混为一谈。
2. 对每个 MOD/版本/变体给出分类、前置、互斥、写入权、许可、状态、应用方式及玩家解释。
3. 同级替换和同版本变体在所有入口互斥：不能同时勾选、导入、快捷键启用、自动随机或恢复。
4. 单控制台提供总览、服装/身体/外观、物理/动作、镜头/摄影、玩法/辅助、画质/性能、音频/界面、工具/配置、诊断/恢复分类。MOD 不能因缺适配器就被隐藏。
5. 不把多个互不兼容的 loader 同时装入一个进程。保留可独立切换的整套配置档，使用退出后事务。
6. 支持工具能力/面板的统一选择和路由；原桌面工具可作为标明“游戏外”的入口，但外部窗口不能算完成对应游戏内面板。
7. 尽可能维持统一身体偏好；按衣服实际 mesh/骨骼/材质策略选配套。没有有效转换的衣服保留自带身体并说明；不同体型、权重或 Physics Asset 不能假装兼容。
8. 玩家看得到效果、冲突原因、崩溃风险证据、显卡压力证据、难度变化、前置缺口、重启要求和恢复方式。
9. 界面近似剑星的视觉语言而不用其受保护 UI 资产；重视层次、体积感、中文、手柄、快捷键、焦点和低开销。
10. 每轮更新唯一状态、验证、正常提交/push 并核对远端。保护个人数据和第三方许可。
11. 任何修改先有可复现原像/拥有文件清单，测试避免覆盖用户存档；保留原游戏、账号和其他任务状态。

## 可证明的兼容，而非无条件承诺

将能力分别记录为“已验证即时”“安全时应用”“重启应用”“缺前置”“已知不兼容”“尚未验证”。同一入口管理所有项，不意味着所有项同时启用。旧版本、互斥替换、无授权接口、缺 DLC 与未知技术限制是显式状态，不能以隐藏它们冒充全部可用。

如果一项仍无法实现用户希望的游戏内控制，就保留该项为未完成/不支持，给出原因、替代操作和下一实验；不能仅因为有外部启动按钮就计入 M1 全部达成。若实测证明需要改变已冻结需求，提交证据给用户决定，不能自行下调目标。

## 验收矩阵

| ID | 原始要求 | 必需证据 |
| --- | --- | --- |
| A01 | 输入完整、分类无漏项 | 固定 hash 清单；每个输入恰有归属，其他游戏/重复/未完成分别统计 |
| A02 | 本机稳定兼容配置 | 当前与候选配置差异、冷启动、读档场景、退出与恢复记录 |
| A03 | 依赖与互斥覆盖全部入口 | UI、导入、快捷键、随机/自动切换、重启事务均阻止同一无效组合 |
| A04 | MOD 完整管理 | 固定版本/变体/功能分母，已适配、停用、未知、未支持分别列出 |
| A05 | 游戏内快捷键控制台 | 本机游戏画面内操作，鼠标/键盘/手柄焦点，关闭恢复输入；不是调试/外部窗 |
| A06 | 服装/皮肤与身体配套 | 每个承诺可用选项的选择回读、资源配套与规定动作/场景视觉检查 |
| A07 | 工具面板与参数 | 对每个承诺支持的控制读/写/回读；生命周期保护与单写入者 |
| A08 | 重启切换与恢复 | 事务中断、源丢失、并发修改、异常退出、失败回滚和冷启动 |
| A09 | 玩家理解与视觉 | 真实玩家流程、状态文案、体积层次、中文/缩放/焦点、危险提示 |
| A10 | 性能与长会话 | 同设置场景帧时间/显存对照、菜单开关/换图、资源释放及结果条件 |
| A11 | 保留真实数据 | 安装/卸载只影响拥有文件；原文件、存档与其他工具未被误删或回滚 |
| A12 | 每轮 GitHub 交付 | 可公开候选、验证结论、提交、远端 HEAD 相等；失败未冒充完成 |
| A13 | 可移植发行 | 新用户从零安装、升级、卸载、恢复；支持的 OS/Proton 版本独立验收 |
| A14 | 开源与许可 | 每个纳入代码/资源的许可与版权通知；无未授权 MOD/游戏资产或秘密 |

M1 使用 A01–A12 与 A14；M2 还要求 A13、公开候选和对应发行授权。完整路线不以检查数量或代码行数算百分比。

每个状态分开记录 static、startup、visual、gameplay、performance、recovery 和 release 验收。规划通过、日志初始化、截图、解析成功和作者描述均不能替代实际产品验收；未运行一律 NOT_RUN。

R01 冻结当前输入分母及可用能力清单。R05、R21、R26 作为阶段验收点；新下载按增量保留原分母。测试数量和性能预算根据实测确定，不在规划里编造 FPS 或“零崩溃”保证。
