## 2. 核心调整：测试公共部分，验证变化部分

不再按“一个 MOD/一套衣服跑完全部流程，再开始下一个”的固定串行方法执行。执行单位是**一组配置共享的行为和一个有意义的修复候选**。

例如：配置 A、B 使用相同游戏版本、加载器、CNS、身体控制器、物理、战斗辅助和按键，全部资源包也已由同一启动加载，只是选中的服装不同。A 已验证的辅助连接、输入恢复、普通移动、公共菜单和共同加载恢复流程，可以直接被 B 引用。B 只补服装自己的加载、材质、身体适配、物理/骨骼差异及必要交互，不重测整套自动防御、重开所有面板、反复完整重启。

这里的“可复用”是可追溯的验收证据，不是默认把相似项目写成 PASS：

| 层次 | 典型内容 | 处理方式 |
| --- | --- | --- |
| 公共基线 | 同版功能模块、唯一写入者、按键、连接、公共输入/恢复 | 验证一次；条件未变则引用同一证据 |
| 同类配置族 | 同骨架、动画蓝图、Physics Asset、身体框架、CNS/原生路线 | 选择结构代表执行共同联动；其余成员引用适用部分 |
| 服装/选项差异 | 新网格、材质、透明遮罩、贴图、独有形变、独有物理 | 只测试受变化影响的断言；缺证据的差异继续待测 |
| 新风险组合 | 两个写入者、不同 loader、额外逻辑包、不同绑定/依赖 | 单列组或反例；不能按“只是换衣服”复用 |

**同名、同作者、同分类、同外观、文件数量相近都不能证明等价。**

## 4. 配置分组与证据有效性

### 4.1 先识别真正的差异

沿用现有 manifest、文件清单、依赖/冲突和结果文件，补充必要关联，不重新复制所有资源。至少分清：

- 功能核心：游戏 build、loader 核心/ABI、启用的 Lua/逻辑模块及相关源码摘要、功能开关、按键、身体/物理/相机/移动/换装各自的写入者。
- 外观路径：原生资源替换、CNS 自定义网格、转换包；实际包版本和资源 ID；原生装备身份与 CNS 当前覆盖选择。
- 结构族：骨架、动画蓝图、Physics Asset、绑定方式、材质槽结构、身体控制支持范围（完整/受限/仅静态）。
- 变化项：网格/材质/贴图/透明或发光行为、形变、独立物理、额外插件、依赖和独有代码。

同一组中只切换已经加载的服装选择，不等于换了功能核心。如果增加/替换了磁盘包，要检查它是否只是内容资源，还是包含全局逻辑、资源覆盖或新的依赖；未知项先保留未知，不能直接继承。

### 4.2 每份证据绑定它实际依赖的条件

复用检查至少回答：证据是哪条断言、绑定哪些输入/版本、实际操作与结果是什么、适用于哪些成员、哪些部分仍缺失、为何仍有效。

不要只用整个 Git HEAD 或日期作有效性开关。文档变化不使游戏测试失效；一次材质修复也不使独立的辅助连接测试失效。反之，相关模块/参数/加载顺序/身体绑定发生变化，即使旧报告仍存在，也要重开受影响断言。驱动/Proton 变化主要重核相应运行、图形和性能证据，不自动重跑纯静态解析。

### 4.3 代表项与差异项

每个结构族选择有依据的代表：普通服装、复杂裙摆/头发、透明/发光、独有骨骼/物理、明显不同身体框架等。代表项建立的是共同机制证据，不替代其他网格的独有视觉检查。

- 只有颜色/贴图变化且几何、骨架、物理和材质机制相同：复用几何/动作证据；补差异材质的加载和必要视图。
- 几何不同、框架相同：复用功能核心；新网格补站立及必要的行走/转身/动作、身体与遮挡检查，不重复全套辅助和冷启动。
- 独有 Physics Asset、骨骼、动画蓝图、身体拓扑或逻辑：另建结构族，补相关动作与生命周期。
- 参数同范围、同消费者和同恢复路径：复用边界/恢复机制；新选项只补独有端点。数值回读不能替代新网格的实际视觉效果。
- 不同包变体覆盖同一资源或存在未知冲突：先解析规则，不能混入一个已通过的组。

### 4.4 失效与增量回归

建立依赖关系“变更的文件/参数/资源 → 受影响能力/断言 → 配置族 → 叶项”。只重跑受影响部分。一个族出问题，暂停该族对应的证据继承，保留公共层与独立族的有效结果；在其他就绪族继续工作。

每次修复先复现反例，再验证修复，再跑最小相邻回归。没有新改动、失败或证据缺口，不再重复整套测试。

## 6. 执行阶段：每阶段交付可复用成果

### S0 接手与适用性审计

读取唯一状态、当前安装/选项和已有证据。检查所有者是否仍在游玩、实际任务/进程所有权、保存与测试隔离条件。固定本轮必要输入摘要及当前失败。先验证本次两项修复的现状，保留真实反例；不因新 Agent/新会话重置历史。

交付：可用公共断言、需重开的断言、各族差异清单和一个下一步。不要先重复全库扫描或建立新测试框架。

### S1 建立一个可玩的公共功能核心

在当前选定组合完成 P0 输入/菜单/恢复、移动持续性与换装归属；保留三项战斗辅助开启。必要时检查同一组合的身体/物理基础联动。满足的公共断言立即登记适用范围，供后续各族引用。

不要求先完成全部外观、极端身体参数和所有历史 MOD，才允许处理一个独立且前置已满足的族。

### S2 按问题族批量修复共享机制

先修影响多个族的共性原因，再处理差异。身体/物理、输入、材质、动画/舞蹈、相机等在依赖允许时按一个会话连续执行一组有意义检查。每批同时记录公共结论、代表项、失败成员和未验证成员；不要在每个叶项后重启一次完整流程。

### S3 外观与参数的增量批次

依现有稳定 ID 分组处理已经就绪的配置族：先代表项、再差异检查。通过公共基线与差异证据组合覆盖成员。新网格的实际加载/外观不能因共用骨架被省略；同网格不同颜色不再重新做所有战斗和菜单测试。

批大小随现场输入成本、资源和故障密度调整。保留未完成批次的精确成员，不重置整批；失败只重开受影响依赖组。

### S4 组合、切换与恢复回归

选择确实准备支持的个人配置档，覆盖原生↔CNS、身体/物理、相机/动作、战斗辅助、对话/过场和重启的主要交互。成对覆盖不足以解释的高风险三方组合单独验证。包/DLL/loader 变化按项目规则退出游戏再部署；仅切换已加载外观选择不自动要求每次冷启动。

公共恢复流程若未变，复用其完整记录，仅补新配置带来的差异。死亡、换图和长会话只在真实数据边界允许的条件进行；缺安全前置则保留 BLOCKED/UNVERIFIED，推进其余检查。

### S5 交付个人可玩配置与剩余问题

交付当前实际启用组合、可复用证据映射、仍有问题的族及精确恢复办法、快捷键和已验证的运行/退出入口。真实长会话/视觉/音频的缺口明确列出。完成本测试修复范围后停止；不自动扩展为管理应用开发或二进制发行。
